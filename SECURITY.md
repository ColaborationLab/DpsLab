# Seguridad de DpsLab

DpsLab trata la seguridad como una condición de diseño, implementación,
publicación y operación. Ningún resultado de pruebas implica por sí solo que
una versión sea segura para usuarios o que pueda distribuirse.

## Reporte responsable

No publiques una vulnerabilidad, secreto, clave, dato personal o procedimiento
de explotación en un Issue público. Mientras el proyecto sea privado, informa
el hallazgo directamente al propietario del repositorio y proporciona sólo la
información mínima necesaria para reproducirlo de forma segura.

Un reporte útil identifica la versión o commit, componente afectado, impacto,
condiciones de reproducción y una prueba no destructiva. No debe incluir claves
privadas, contraseñas, tokens, datos de personajes ajenos ni contenido con
restricciones de redistribución.

## Respuesta

Un hallazgo válido se clasifica antes de corregirse. La respuesta puede
cuarentenar una versión, suspender actualizaciones, revocar una clave pública o
desactivar una fuente. Diagnóstico, corrección, auditoría, publicación y
activación son decisiones separadas.

No existe todavía una versión pública soportada. Antes de una beta externa,
DpsLab debe disponer de canal privado de reporte, inventario de componentes,
escaneo de dependencias y secretos, análisis estático, pruebas adversariales y
procedimientos de revocación y recuperación ejercitados.

## Alcance

La política cubre la aplicación de escritorio, el futuro addon, paquetes de
conocimiento, fuentes externas, canal de actualización, herramientas de
compilación, GitHub Actions y material criptográfico de publicación.
